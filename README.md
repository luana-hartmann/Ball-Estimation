# Ball-Estimation — 2D ball trajectory extraction

Image-processing component of the Spinsight-inspired table tennis analysis
project. Extracts a 2D pixel trajectory of the ball from raw video, to be
handed off to the trajectory/spin estimation model.

## Structure

```
src/            current, maintained pipeline (see below)
archive/        earlier design iterations (v1-v3) and an abandoned Kalman-
                filter experiment (v5). Not maintained, not imported by
                anything in src/. Kept because the report discusses *why*
                each of these was tried and replaced -- see report section
                "Design iterations".
data/<name>/    one folder per video: <name>.mp4, ball_markup_<name>.json,
                events_markup_<name>.json
outputs/        everything generated by running the pipeline (gitignored,
                regenerate anytime with `make`)
```

## Pipeline (src/)

Three stages, all inside `src/detector.py`:
1. Motion detection (3-frame differencing)
2. Candidate filtering (size, aspect ratio, brightness/saturation
   *relative to local surroundings* -- see report for why relative
   beats absolute here)
3. Motion-continuity tracking (typicality-weighted candidate selection)

Other scripts in `src/`:
- `evaluate.py` -- compares a trajectory CSV against ground truth, reports
  recall/precision/pixel error/miss-streak
- `calibrate.py` -- measures real threshold values from ground-truth ball
  contours, instead of guessing them
- `diagnose_fn.py` / `diagnose_wrong_pos.py` -- pull the actual worst-case
  frames (missed / wrongly-tracked) and show exactly why, calling the real
  detector logic directly (not a re-implementation) so this can't silently
  drift out of sync with the detector
- `inspect_ball_patches.py`, `verify_ball_markup.py` -- one-off sanity/
  calibration helpers

## Setup

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Usage

Everything is driven through the Makefile so thresholds stay consistent
across every step (this is deliberate -- see report for the bug this
was built to prevent).

```bash
make all NAME=test2      # runs detection + evaluation for data/test2/
make diagnose NAME=test2 # investigate missed frames
make clean NAME=test2    # remove generated files, force a clean rerun
```

Each video needs its own folder under `data/`, e.g.:
```
data/test2/test2.mp4
data/test2/ball_markup_test2.json
```

## Notes

- Thresholds in the Makefile were calibrated on `test_2` only and verified
  (not just assumed) to generalize reasonably to `test_5`/`test_6` without
  retuning -- see report for the full generalization test and the
  absolute-vs-relative-feature tradeoff it revealed.
- Make does not know when *logic* (not just inputs) has changed --
  if you edit a script, `make clean NAME=<x>` before rerunning, or Make
  will silently reuse a stale output file.
